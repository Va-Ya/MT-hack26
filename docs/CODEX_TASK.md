# ТЗ на объединённую локальную версию

## Приоритеты

1. База — архив `transport_service_integration.zip`. Не изменять ML, модели, обучение, зависимости ML, submission и исходные ML-тесты. Не заменять уже интегрированные stop detection и NDTP старым кодом.
2. Перенести внешний контекст, сценарии и новый интерфейс из предыдущей локальной версии. Backend объединять по изменениям, сохраняя вызовы новой модели, настройки времени и readiness.
3. Добавить отдельный раздел обучения для неподготовленного пользователя. Объяснить запуск истории, поиск проблемы, проверку источников и сценарное решение. Включить примеры значений, честное описание отсутствующих данных и поиск по частым вопросам.
4. Сохранить белую тему, строгую структуру и жёлтые акценты. Главный мониторинг должен показывать карту и очередь проблем; обучение, источники, настройки и сценарии доступны из отдельной навигации.
5. Не отправлять изменения в GitHub до отдельного разрешения пользователя.

## Источники и расчёты

- Погода — Open-Meteo, с единицами, временем источника, временем получения, модельной природой и статусом свежести.
- Дорожные события — нормализованный EventFeed с координатами, периодом действия и ссылками. Без подтверждённого API ЦОДД обозначать статус «не подключён», не подставлять происшествия.
- Яндекс Карты — JS API v3 с ключом пользователя. Не считать лицензированные визуальные слои экспортируемой выборкой для ML.
- Исторические и текущие данные разделять. Признак LIVE сам по себе не доказывает совпадение часов.
- Сценарии: t=3600L/v, изменение оборота через изменение времени участка, H=C/N, E[W]=H/2. Допущения показывать пользователю; резерв вне горизонта не учитывать.
- Привязка маршрутов — геометрический baseline, неоднозначные точки помечать; не придумывать route_id для транспорта.

## Приёмка

- Проверка SHA-256 сохранённых компонентов без изменений.
- Проход исходных и добавленных тестов, проверка TypeScript, проверка сборки и UI при доступном окружении.
- Ручной сценарий: Обучение → Мониторинг → зона → Факторы → Сценарии; все разделы доступны без ключа карты.
- Ошибки источников, отсутствие модели и отсутствие датасета обозначены понятными состояниями.
- Непроверенные интеграции и ограничения записаны в MERGE_REPORT.md, без утверждения о завершённости недоступных проверок.
