Инструкция для жюри

Архитектура

ML-ядро — модуль ml: причинные признаки и ансамбль трёх CatBoost-моделей. Backend — FastAPI: приём сообщений, состояние ТС, расписание, вызов ML и API. BI — React: положение ТС, зоны риска, карточки, прогноз/факт и метрики. Backend вызывает ML внутри одного Python-процесса. Контейнер ml в Compose выполняет проверку модели и завершается; это не отдельный сетевой сервер инференса. Render объединяет модули в одном образе. Локальный Compose разделяет backend и BI.

Запуск без полного датасета

Из корня проекта выполните:

docker compose up --build -d
docker compose ps

Компактные оригинальные демо-данные включены. Дашборд: http://localhost:8080. Swagger: http://localhost:8000/docs. Метрики: http://localhost:8000/metrics. Compose запускает управляемый исторический replay автоматически. Пауза и перемотка в интерфейсе управляют тем же потоком. Время источника берётся из датасета.

Опубликованный сайт

Откройте корень сайта: исторический поток запускается автоматически. Под картой доступны пауза, скорость и перемотка. Без ключа API доступна карта OpenStreetMap с реальными зонами наблюдений. API: /api/docs, метрики: /api/metrics. Подготовка восстанавливает 20 минут истории. Состояние демо общее для посетителей. Бесплатный Render может пробуждаться около минуты; после перезапуска демо начинается заново.

Где увидеть результат

Выберите «Прогноз 10–15 мин» и зону из «Требуют внимания». Карточка показывает прогноз задержки, текущее отклонение, индекс риска и наблюдаемые факторы. Просматривайте зоны в текущем режиме и в прогнозе. Наличие алерта зависит от реальных данных; искусственные задержки для показа не добавляются. Выберите ТС и выданный прогноз: после поступления факта появятся ошибка и упреждение. Факт не используется моделью до его доступности. Горизонт задаётся относительно планового события; фактическое упреждение отображается отдельно. Risk score — объяснимый индекс, не калиброванная вероятность задержки.

Полный исторический датасет

Распакуйте train, test, validate, labels и sample_submission.csv в data/raw. В .env задайте DATA_DIR=/app/data/raw и перезапустите Compose. Для внешнего CLI-потока сначала переключите интерфейс в LIVE. С установленными Python-зависимостями можно выполнить:

python -m emulator.replay --data data/raw --split test --speed 50

CLI и встроенный replay нельзя подавать одновременно. Для сайта адрес CLI API — https://ВАШ-САЙТ.onrender.com/api, параметр --url. INGEST_TOKEN задаётся в окружении.

Официальный NDTP-эмулятор локально

Образ организаторов не включён в Git. Выполните docker load -i с путём к ndtp-telemetry-emulator.tar, затем запустите образ ndtp-telemetry-emulator:1.0 с портом 18080:18080 и --add-host=host.docker.internal:host-gateway. В .env включите NDTP_ENABLED=1, NDTP_UNIT_MAP задайте по device unit_id → tr_id. Для демо соответствие находится в demo/ndtp-unit-map.json. Перезапустите backend и переключите интерфейс в LIVE. Через POST http://localhost:18080/api/config задайте targetHost=host.docker.internal, targetPort=9201 и реальные unitId. Проверка приёма: /ndtp/status, /vehicles, /metrics. Пример конфигурации: demo/ndtp-config.json; autoGenerate создаёт случайное движение, поэтому подходит для проверки протокола, но не для оценки качества прогнозов.

Эмулятор сам ставит текущий UNIX timestamp. Историческое расписание может не соответствовать этой дате. Для содержательных прогнозов необходимы согласованные время, расписание и траектории. SCHEDULE_FILE указывает расписание внутри контейнера; NDTP_TIMEZONE — подтверждённую шкалу. Перенос даты допускается только как явно отмеченный стендовый режим через NDTP_CLOCK_OFFSET_SECONDS; по умолчанию переноса нет. DETECT_STOPS=1 включает осторожное GPS-подтверждение остановки, но неоднозначные события не создаёт. При историческом replay оставьте DETECT_STOPS=0.

Подача NDTP на Render

Эмулятор подключается к локальному TCP-мосту, а мост отправляет исходные проверенные кадры по HTTPS в /api/telemetry/ndtp. Установите зависимости Python и выполните:

$env:INGEST_TOKEN="ТОКЕН ИЗ RENDER"
python -m emulator.ndtp_bridge --host 0.0.0.0 --port 9201 --url https://ВАШ-САЙТ.onrender.com/api

Настройте эмулятор на host.docker.internal:9201. В интерфейсе введите операторский токен и переключитесь в LIVE. Ограничьте доступ к порту моста локальным стендом. Мост не воспроизводит историю после обрыва: закрывает соединение, эмулятор подключается заново. Raw TCP напрямую на HTTP-порт Render не подаётся. Проверка официального эмулятора и даты должна быть подтверждена отдельным протоколом испытаний; наличие декодера и unit-тестов не заменяет её.

Проверки и документация

README описывает сборку. /api/docs содержит интерактивный OpenAPI на сайте; локально используется :8000/docs. Сгенерированный PyDoc — в /documentation/. Описание измерений и дополнительных функций: PERFORMANCE.

Погода и время

WEATHER_ENABLED=true включает Open-Meteo как отдельный контекст, без изменения ML. LIVE запрашивает текущую погоду около выбранной точки; REPLAY — почасовую архивную погоду за дату курсора. Архив является ретроспективным реанализом, не доказательством доступности погоды на момент выдачи прогноза. Внешние запросы выполняются в фоне; при ошибке показан статус, прогнозирование продолжается. В /api/external/context указаны mode, reference_time, retrospective, timezone, координаты ячейки и источник.

В предоставленном датасете проверены 4787 строк: T совпадает с UNIX-суффиксом sample_id при трактовке T как UTC. Облачный образ использует TELEMETRY_TIMEZONE=UTC; для другого потока требуется указать его реальную шкалу. Погодные даты показываются в МСК.

/api/metrics содержит actual_lead_time: фактическое время события минус время прогноза, число прогнозов с упреждением 600–900 секунд и число прогнозов не раньше события. Повторные прогнозы считаются отдельно. Плановый горизонт 600–900 секунд не гарантирует такое же фактическое упреждение, replay_mae не является скором лидерборда.

Подтверждённые ограничения

ML выделен программным модулем, но инференс работает внутри процесса backend. Отдельного постоянно работающего ML-сервиса пока нет. Индекс риска — правило агрегации, не калиброванная вероятность. Сеть маршрутов загружается оператором; географические зоны не являются административными районами или полноценной маршрутной сетью. NDTP извлекает NAV00: координаты, скорость и направление; датчики дверей пропускаются. Погода и дорожные события не являются автоматически установленными причинами задержки.
