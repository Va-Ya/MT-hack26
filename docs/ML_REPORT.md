# ML: результаты и ограничения

## Данные и причинность

Источник — архив пользователя, полный аудит в `artifacts/audit.json`, подтверждённые ключи в `docs/DATA_MODEL.md`. В train 4434 размеченных объекта, в test 353, в validate 151. Исторические аналоги points уже поставлены в labels; создавать вымышленные связи рейсов не потребовалось. Все targets проверены по расписанию. Плановый horizon лежит в (600,900] с; медиана — 660 с.

FeatureBuilder общий для обучения, submission и streaming. Допускаются только event_time, receive_time и gps_time <= T, окно истории 20 минут. План будущей остановки разрешён; её факт не передаётся в признаки. Пропуски GPS/скорости остаются пропусками, 0 не подставляется. В 1318 из 4434 training samples нет свежей валидной скорости. Cur_dev_s — официальная известная на T подсказка.

## Temporal validation

Граница: 2026-01-06 15:55:00 в исходной шкале времени. Train: 3055 ранних примеров; validation: 1338 поздних, включая 333 реальных. 41 ранний объект исключён, потому что плановое/фактическое событие ещё не наступило к границе. Перемешивание не используется.

| Эксперимент | Деревья | MAE весь temporal holdout | MAE реальные ТС |
|---|---:|---:|---:|
| cur_dev_s baseline | — | 97.60 с | 95.55 с |
| CatBoost: контекст | 108 | 90.44 с | 89.30 с |
| CatBoost: контекст + телеметрия | 122 | 90.00 с | **89.16 с** |
| + categorical target_stop_id | 184 | 89.13 с | 89.57 с |

Выбран telemetry по MAE реальных ТС в temporal holdout. Относительное улучшение к baseline — около 6.7%. CatBoostRegressor учит поправку к cur_dev_s, loss MAE, depth 6, learning_rate .05, максимум 1000 итераций, early stopping 80, random_seed 42, CPU 4 потока. Фактические итерации выбраны на temporal split. Финальная модель переобучена на labels_train, без labels_test и без фактов validate.

Отдельная проверка того же раннего temporal model на поздней части официального test: 103 примера, **78.50 с против 88.19 с baseline**. Это дополнительная оценка, не использованная для выбора эксперимента. После финального fit на всём train MAE всего test — 79.42 с против 93.36 с, но такая оценка не является temporal holdout, потому что периоды train/test пересекаются.

## Важность и ошибки

Важность признаков temporal model: cur_dev_s 45.23%, расстояние до плановой точки 5.90%, час 5.13%, heading 5.03%, средняя скорость за 3 минуты 2.93%. Важность не является причинным эффектом; полный файл — `artifacts/feature_importance.csv`.

Срезы ниже относятся к полному temporal holdout (реальные + синтетические ТС):

- В 18 и 19 часов MAE 144.07 и 151.93 с, выше, чем в 16 часов (68.14 с). Часы в шкале источника; timezone не доказан.
- При текущем опоздании >300 с MAE 197.52 с (148 примеров).
- При целевом опоздании >300 с MAE 216.49 с (142 примера). Модель недостаточно точно предсказывает крайние задержки.
- Для целевого отклонения (0,120] с MAE 55.33 с (480 примеров).
- Срезы по ТС и target_stop_id сохранены в `artifacts/error_analysis.csv`. Target_stop_id уникален для события, поэтому срез на событие имеет n=1 и не является устойчивой оценкой физической остановки.
- Route_id отсутствует: анализ по маршрутам не проводится. Tr_id не выдаётся за маршрут.

## Submission и streaming

`artifacts/submission.csv`: UTF-8, `sample_id;prediction`, 151 строка, полное совпадение ID с шаблоном, без дублей и нечисловых значений. Features пересчитываются из validate/traffic и schedule_plan, без доступа к test/schedule фактам.

Реальный HTTP replay 15:50–16:20 обработал 2685 событий и 1734 прогноза. Среднее время признаков 7.47 мс, P50 7.30 мс, P95 10.35 мс; inference 2.52 / 2.40 / 3.37 мс; сумма признаков и inference 9.99 / 9.80 / 13.30 мс. Измерения зависят от машины и текущей нагрузки, не являются гарантией SLA. HTTP, запись Parquet и очередь вне этого таймера.

Для 1075 прогнозов уже наступил факт, MAE этого replay 71.47 с. Это много перекрывающихся прогнозов на одни события, а не 1075 независимых тестовых примеров. Сравнивать это число напрямую с competition MAE нельзя. Замеры сохранены в `artifacts/replay_metrics.json`.

## Ограничения

Датасет охватывает примерно сутки; train содержит синтетические ТС. Test/validate используют одинаковую телеметрию, но непересекающиеся sample_id и целевые события. Нужна проверка на новых днях и независимых рейсах перед эксплуатацией. Риск — объяснимый индекс, не вероятность. География прогноза относится к текущим местоположениям ТС; будущие координаты не моделируются.

Поток при отсутствии известного cur_dev_s использует 0 с явным флагом current_delay_known=False. Replay раскрывает факты только по времени их наступления и передаёт официальные cur_dev_s на оригинальных размеченных точках. В живой интеграции нужны наблюдаемые события остановок/текущая задержка. NDTP TCP decoder не реализован: MVP принимает уже декодированную телеметрию CSV через HTTP.
