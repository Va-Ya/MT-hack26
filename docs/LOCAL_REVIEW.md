# Локальная объединённая версия

Основа — предоставленный `transport_service_integration.zip`. Эта папка отделена от предыдущей версии, GitHub не изменён.

## Запуск на этом компьютере

Откройте PowerShell в папке `transport_service_local` и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1 -BackendPort 8010 -FrontendPort 5174
```

Интерфейс: http://127.0.0.1:5174. API: http://127.0.0.1:8010/docs.
Порты отличаются от предыдущего проекта, чтобы не перепутать версии. Остановка своих процессов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-local.ps1
```

На этом компьютере `.local-runtime.json` указывает на уже установленные Node.js и Python из предыдущей рабочей папки. Эти пути не входят в архив и не нужны другим участникам.

## Первый запуск на другом компьютере

Установите Python 3.12 и Node.js 24. Из папки проекта:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
npm --prefix dashboard ci
Copy-Item .env.example .env
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1
```

С этими стандартными портами интерфейс открывается на http://127.0.0.1:5173, API — http://127.0.0.1:8000/docs.
Исходные данные хакатона размещаются в `data/raw`. В этой локальной папке CSV уже есть, в передаваемый архив не включены.

## Сценарий ручной проверки

1. Откройте **Обучение** слева. Изучите четыре шага, отметьте их прочитанными, проверьте переход к соответствующему разделу и поиск по справке.
2. В **Мониторинге** запустите историю жёлтой кнопкой. Дождитесь подготовки и появления транспорта. Выберите зону; подробности расположены под картой.
3. Переключите «Сейчас» / «Прогноз 10–15 мин», проверьте поиск и фильтры. Перемотка пересобирает историю и заканчивается паузой.
4. В **Факторах** проверьте дату погоды, ссылку на источник и статусы свежести. Раскройте формулы. Текущая погода не изменяет исторический ML-прогноз.
5. В **Сценариях** учебные параметры дают 240 → 510 секунд, изменение +270 секунд, интервал около 5,86 минуты. Выпуск резерва через 16 минут при горизонте 15 не учитывается.
6. В **Данных** доступны инструкции и импорт маршрутов/дорожных событий. Настройка Яндекса: `VITE_YANDEX_MAPS_API_KEY` в корневом `.env`, затем перезапуск интерфейса. Без ключа — координатная схема.

## Защита ML и NDTP

Сохранены ML-код, настройки обучения, модели и metadata, входящий NDTP-приёмник, подтверждение остановок, исходные тесты, эмулятор и контрольные артефакты. Контроль:

```powershell
python scripts/verify-preserved.py
```

`INTEGRATION_README.md` содержит неизменённую инструкцию автора ML-интеграции. Для исторического replay `NDTP_ENABLED=0` и `DETECT_STOPS=0`. Для NDTP используются исходные `NDTP_UNIT_MAP`, `NDTP_TIMEZONE` и `SCHEDULE_FILE`; старый параметр `NDTP_UNIT_MAP_PATH` из предыдущего проекта сюда не переносится.

## Источники и ограничения

- Open-Meteo: модельная погода для одной ячейки в центре Москвы, с датой и единицами.
- Яндекс: подготовлено подключение JS API v3; ключ не предоставлен. Слои пробок и событий требуют соответствующего тарифа.
- ЦОДД: подготовлен адаптер согласованного JSON-источника `CODD_FEED_URL` и импорт `EventFeed`. Рабочий официальный endpoint не подтверждён; живой поток не подключён.
- Геометрия маршрутов импортируется из проверенного источника. Привязка — геометрический baseline, не восстановление отсутствующих маршрутных идентификаторов.
- Docker-конфигурация сохранена с проверкой исходной модели. Автоматическое обучение при запуске не добавлялось. Полный контейнерный запуск с официальным эмулятором требует работающего Docker Engine.
