# Интеграция победившей ML-модели

Архив содержит снимок репозитория с моделью из присланного trained_models.zip.
Он не отправлен в GitHub. При переносе в рабочий репозиторий согласуйте изменения
backend/app.py и docker-compose.yml с участником, отвечающим за деплой.
Изменения dashboard в этот этап не входят.

## Проверки

- Версия модели e44988f343f4, causal-v3, три CatBoost-модели.
- SHA256 всех участников ансамбля проверены.
- Все 151 прогноза совпадают с присланным submission (33).csv с погрешностью округления.
- Потоковый и офлайн прогноз проверяются на одинаковой телеметрии и расписании.
- Тесты проверяют отсечку по времени, задержанные сообщения и исходы, NDTP CRC,
  дробление TCP-пакетов, переподключение, подтверждение остановки и срок прогноза.
- Официальный Docker-эмулятор пока не проверен: Docker Engine на этой машине выключен.

## Запуск

Распакуйте исходные данные в data/raw, как раньше. Включите Docker Engine.
Из корня распакованного проекта: docker compose up --build.
Backend: http://localhost:8000/docs, dashboard: http://localhost:8080.
GET /health возвращает 503, если модель не загрузилась; /health/live проверяет процесс.
Контейнер ml теперь только проверяет модель и хеши: обучение и чтение labels при старте исключены.

## NDTP

В .env укажите NDTP_ENABLED=1. TCP доступен на localhost:9201.
NDTP_UNIT_MAP — JSON-сопоставление unitId и tr_id из расписания, например {"17":"123"}.
Выберите LIVE в контроллере replay перед отправкой внешней телеметрии.
POST /telemetry/ndtp принимает бинарный пакет handshake + realtime (одной пачкой),
использует существующую авторизацию INGEST_TOKEN и ограничивает запрос размером 1 MiB.
TCP соединение требует handshake перед realtime; неизвестные типы ячеек отклоняются.
NDTP_TIMEZONE=UTC задаёт шкалу времени расписания. Она должна соответствовать данным.
Историческое расписание за январь нельзя напрямую применять к сегодняшнему UNIX времени
эмулятора. Подготовьте расписание для демонстрации и укажите SCHEDULE_FILE.
Не выдавайте искусственный перенос времени за работу с настоящим текущим расписанием.

DETECT_STOPS=1 включает консервативное GPS-подтверждение прибытия: радиус 50 м,
скорость <=3 км/ч, минимум 15 секунд наблюдений, разрыв <=30 секунд.
При неоднозначной остановке факт не создаётся. В историческом replay оставьте 0:
там подтверждённые исходы передаются отдельно. Неизвестное текущее опоздание помечается
current_delay_known=false; нулевой вход модели в таком случае — fallback, а не известный факт.

## Что делать команде

Backend/деплой: применить файлы ml/, backend/, models/ и изменения compose,
включить Docker, прогнать tests и связку с официальным эмулятором.
Frontend: подключить Leaflet/OSM, показать неизвестное опоздание и состояние потока,
не называть risk_score вероятностью: сейчас это объяснимый индекс риска.
Презентация: сохранить скрин 0.93301, объяснить отсечку T и независимые модули.
Следующие этапы: отдельный калиброванный классификатор вероятности задержки,
What-if, map matching, честно обозначенные ручные/демонстрационные дорожные события,
публичный деплой и замеры latency. Эти этапы этим архивом ещё не закрыты.
